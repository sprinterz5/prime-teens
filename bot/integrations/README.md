# Синхронизация с Google-таблицей

Заказчик ведёт группы/менторов/учеников в Google-таблице. `sheets_sync.gs` —
скрипт, который вставляется прямо в эту таблицу (Apps Script) и публикует
её как Web App — небольшую HTTP-ссылку, которую **бот сам дёргает по
расписанию**.

**Как это работает.** Бот живёт на домашней машине на long polling —
публичного адреса у него нет, вебхук не подходит. Но это не мешает боту
самому сходить куда-то по обычной ссылке: HTTP-запрос ИЗ бота наружу не
требует, чтобы у бота был свой публичный адрес — нужен он только для
запросов ВОВНУТРЬ. Поэтому схема простая: скрипт публикует таблицу как
Web App (эндпоинт `doGet`), бот раз в ночь (и по команде `/sync_sheet`
в любой момент) делает обычный `GET` по этой ссылке с секретным токеном и
получает JSON в ответ.

> **Было по-другому, не сработало.** Первая версия делала наоборот: скрипт
> сам слал файл боту через Bot API (`sendDocument`). Не заработало — с точки
> зрения Telegram такое сообщение отправляет САМ БОТ, а бот получает через
> `getUpdates` только то, что ему прислали люди, а не эхо своих же исходящих
> вызовов. Файл просто лежал в чате, и ничего не происходило. Пул-схема
> (бот сам идёт и забирает) устроена ровно наоборот и работает.

**Скрипт ничего не парсит.** `doGet` просто выгружает нужный лист целиком —
`getDataRange().getValues()` — и отдаёт эту сырую сетку JSON'ом. Весь разбор
(где начинается блок группы, где шапка колонок, где строка-маркер) — на
стороне бота, в `app/roster_sheet.py`. Так специально: если формат таблицы
чуть изменится, разбор правится перезапуском бота, а не переклейкой этого
скрипта в саму таблицу.

---

## 1. Как устроен лист

Один лист, сверху вниз идут блоки групп, между блоками — пустые строки.
Форматирование (границы, заливка) значения не имеют — важен только текст.

Блок группы:

```
Группа 1 |     |     | Утренняя | 21 сентября | Онлайн        <- строка-заголовок блока
Ментор   | Номер телефона | # | Ученик | Контакты | Школа | Класс   <- шапка колонок
Ерлан Тестов | 7 700 111 71 13 | 1 | Тестов Арман Серикулы | 7 700 111 0070 | НИШ IB | 8
                                   | 2 | Примеров Амир        | 7 700 111 7957 | РФМША  | 7
                                   | 3 | ...
```

**Строка-заголовок блока.** Название группы, смена («Утренняя»/«Вечерняя»),
дата старта и формат («Оффлайн»/«Онлайн») могут стоять в любой из колонок
этой строки — бот ищет их по смыслу значения, а не по фиксированной позиции.
Дата — либо настоящая дата (если ячейка отформатирована как дата, Google
отдаёт её как реальный объект, год берётся из неё напрямую), либо текст вида
«27 июля» (без года — тогда бот сам подбирает ближайший подходящий год) или
«27.07.2026» / «2026-07-27».

**Шапка колонок.** Обязательные заголовки: «Ментор», «Ученик». Остальные —
«Номер телефона», «#», «Контакты», «Школа», «Класс» — тоже ищутся по
названию, порядок колонок не важен. «Номер телефона» может отсутствовать
(бывает в реальных таблицах) — тогда бот берёт телефон ментора из колонки
сразу справа от «Ментор».

**Строки учеников.** «Ментор» и «Номер телефона» заполнены только в первой
строке блока — дальше это выглядит как объединённая ячейка, а на деле
просто пусто; бот сам «протягивает» эти значения вниз до конца блока. Если
в одном блоке несколько разных менторов — это нормально, каждый учитывается.
«#» — просто порядковый номер, не используется. Строка без имени в колонке
«Ученик» пропускается молча (считается в отчёте, не как ошибка).

## 2. Строка-маркер «Настоящие группы отсюда:»

Сверху таблицы обычно лежат демонстрационные блоки «Шаблон» и «Пример» —
их импортировать нельзя. Ниже них должна быть отдельная строка с текстом
**«Настоящие группы отсюда:»** (регистр и пробелы/двоеточие не важны,
достаточно, чтобы строка содержала «настоящие группы»). Всё, что НИЖЕ этой
строки — реальные данные, разбираются и попадают в бота. Всё, что выше
(включая саму строку-маркер) — игнорируется.

Если маркер не найден — бот разберёт всю таблицу целиком (включая
Шаблон/Пример) и явно предупредит об этом в отчёте.

## 3. Открыть Apps Script в таблице

В Google-таблице: **Расширения → Apps Script**. Откроется отдельная
вкладка с редактором кода — это отдельный мини-проект, привязанный к данной
таблице.

## 4. Вставить код

В редакторе слева уже есть файл `Код.gs` (или `Code.gs`) — стереть всё, что
там есть, и вставить целиком содержимое [`sheets_sync.gs`](./sheets_sync.gs)
из этого репозитория. Сверху в блоке настроек заполнить:

```js
var SHEET_SECRET = 'ВСТАВЬ_СЮДА_СЛУЧАЙНУЮ_СТРОКУ';
var SHEET_NAME = 'Группы';
```

`SHEET_SECRET` — **не токен бота**, отдельный случайный пароль только для
доступа к этой ссылке (сгенерировать: любой генератор UUID/пароля, или
попросить у того, кто настраивал бота — он уже сгенерирован и лежит в
`.env` бота как `SHEETS_SYNC_TOKEN`, впиши сюда то же самое значение).

`SHEET_NAME` — точное название вкладки листа с реальными данными (как
написано внизу таблицы). Не «активный лист» специально: ночной автозабор
бота не должен зависеть от того, какую вкладку кто-то последним открывал.

Сохранить: значок дискеты или `Ctrl+S` (`Cmd+S` на Mac).

## 5. Опубликовать как Web App

**Deploy → New deployment** (кнопка «Начать развёртывание» справа вверху
редактора). В открывшемся окне:

1. Рядом с «Select type» нажать шестерёнку ⚙ и выбрать **Web app**.
2. **Execute as** — «Me» (твой аккаунт: скрипт должен читать таблицу твоими
   правами, а не правами того, кто позже дёрнет ссылку).
3. **Who has access** — «Anyone» (без этого бот, у которого нет твоего
   Google-аккаунта, не сможет постучаться в ссылку; доступ к данным всё
   равно защищён `SHEET_SECRET`, а не настройками Google).
4. **Deploy**.

Google покажет запрос на авторизацию, а следом — экран
**«Приложение не проверено»** («Google hasn't verified this app»). Это
нормально и ожидаемо: скрипт свой, для одной конкретной таблицы, в каталог
Google Workspace Marketplace не публиковался — поэтому автоматической
проверки не проходил. Чтобы продолжить:

1. Нажать **«Дополнительные настройки»** («Advanced») внизу экрана.
2. Нажать **«Перейти на страницу … (небезопасно)»** («Go to … (unsafe)»).
3. Разрешить доступ к таблице кнопкой **«Разрешить»**.

После деплоя Google покажет ссылку вида
`https://script.google.com/macros/s/XXXXXXXXXXXX/exec` — это и есть URL для
бота. Скопировать её. (Если окно уже закрыл — **PrimeTeens → Показать
ссылку для бота** в меню таблицы покажет её снова.)

## 6. Отдать ссылку и секрет боту

В `.env` бота:

```
SHEETS_SYNC_URL=https://script.google.com/macros/s/XXXXXXXXXXXX/exec
SHEETS_SYNC_TOKEN=<та же строка, что в SHEET_SECRET>
SHEETS_SYNC_HOUR=3
```

`SHEETS_SYNC_TOKEN`, скорее всего, уже сгенерирован и лежит в `.env` —
проверить и, если нужно, переставить в `SHEET_SECRET` внутри скрипта то же
значение. `SHEETS_SYNC_HOUR` — час ночного автозабора (0–23, по часовому
поясу бота, `TZ` в `.env`). Бот подхватит новые значения при следующем
перезапуске (`run.bat`).

## 7. Проверить

В таблице: **PrimeTeens → Проверить настройки** — секрет задан, нужный лист
есть и не пуст.

В боте (у администратора): команда **`/sync_sheet`** — заберёт данные
немедленно и пришлёт отчёт: что создал, что обновил, какие строки не
прошли (с номером строки — там же видно, что чинить в таблице), и отдельно
— распознанную дату старта каждой группы (чтобы заметить ошибку угадывания
года, если дата в таблице была текстом без года).

## 8. Автосинхронизация

Отдельно ничего включать не нужно — если `SHEETS_SYNC_URL` заполнен в
`.env`, бот сам проверяет раз в 30 минут, не настал ли час `SHEETS_SYNC_HOUR`,
и раз в сутки в это время делает `/sync_sheet` сам, без участия человека.
Отчёт придёт в личку каждому, чей Telegram ID есть в `ADMIN_IDS`.

Никакого триггера СО СТОРОНЫ ТАБЛИЦЫ настраивать не нужно — расписание
целиком на стороне бота, `doGet` в скрипте просто отвечает по запросу, когда
бы он ни пришёл.

---

## ⚠️ Секрет всё же стоит беречь

`SHEET_SECRET` — не токен бота (тот в этой схеме таблице вообще не нужен,
и это специально: раньше он лежал в скрипте открытым текстом, теперь не
лежит). Но с этим секретом и знанием ссылки кто угодно может ЗАБРАТЬ данные
листа — телефоны и имена детей и менторов. Поэтому:

- Менторам и всем, кому нужно только заполнять таблицу — доступ **только на
  просмотр/редактирование данных**, но не на **Apps Script** (там секрет
  виден в коде). Права на саму таблицу и права на её скрипт разделены в
  Google независимо — можно дать доступ к листам, не давая доступа к
  «Расширения → Apps Script».
- Если секрет «утёк» — поменять `SHEET_SECRET` в скрипте на новую строку,
  пересохранить (для Web App изменения кода требуют **Deploy → Manage
  deployments → редактировать существующий деплой → New version**, иначе
  правки не подхватятся) и обновить `SHEETS_SYNC_TOKEN` в `.env` бота.

## Формат JSON, который отдаёт `doGet`

Бот делает `GET <SHEETS_SYNC_URL>?token=<SHEETS_SYNC_TOKEN>`, скрипт отвечает:

```json
{
  "ok": true,
  "source": "google-sheets",
  "spreadsheet": "Название файла таблицы",
  "sheet": "Название активного листа",
  "exported_at": "2026-09-03T10:00:00.000Z",
  "rows": [
    ["", "Шаблон — образец, не импортируется"],
    [],
    ["Группа А", "", "", "Утренняя", "27 июля", "Оффлайн"],
    ["Ментор", "Номер телефона", "#", "Ученик", "Контакты", "Школа", "Класс"],
    ["Айгерим Смагулова", "+7 700 000 00 01", 1, "Иванов Иван", "+7 700 000 00 02", "НИШ", 9],
    [],
    ["Настоящие группы отсюда:"],
    [],
    ["Группа 1", "", "", "Утренняя", "2026-09-21", "Онлайн"],
    ["Ментор", "Номер телефона", "#", "Ученик", "Контакты", "Школа", "Класс"],
    ["Ерлан Тестов", "7 700 111 71 13", 1, "Тестов Арман Серикулы", "7 700 111 0070", "НИШ IB", 8]
  ]
}
```

`rows` — сырая сетка листа: строка листа = элемент массива, ячейка = элемент
строки. Именно это — а не заранее разобранные списки групп/менторов/
учеников — идёт боту: весь разбор блоков делает `app/roster_sheet.py` на
стороне бота.

Если что-то не так (неверный `token`, лист `SHEET_NAME` не найден,
`SHEET_SECRET` не настроен), `doGet` отвечает тем же HTTP 200 — ContentService
не даёт ставить другой статус, — но с `"ok": false` и `"error"`:

```json
{"ok": false, "error": "неверный или отсутствующий token"}
```

Бот проверяет именно поле `ok`, а не код ответа, и печатает `error` как есть.

**Про даты в ячейках.** Если ячейка отформатирована как дата, Google Sheets
хранит её как объект даты — при выгрузке в JSON скрипт форматирует такую
ячейку строкой `ГГГГ-ММ-ДД` В ЧАСОВОМ ПОЯСЕ САМОЙ ТАБЛИЦЫ (а не UTC) —
это специально сделано в `dateSafeValue_()`, чтобы дата не «съехала» на
день назад при сериализации в JSON (обычный `JSON.stringify` от объекта
Date даёт UTC-таймстамп, и, например, полночь 27 июля в Алматы (+5) стала
бы «26 июля» после наивного разбора на стороне Python). Если же ячейка
текстовая («27 июля» без года) — она уходит как есть, бот сам разберёт и,
если года нет, подставит ближайший подходящий по правилу «не более 120 дней
в прошлом, иначе следующий год» — и всегда покажет распознанную полную дату
в отчёте, чтобы это угадывание можно было проверить глазами.

Синхронизация идемпотентна и ничего не удаляет: повторная отправка того же
листа не плодит дубли — группы и ученики обновляются (upsert по
названию/ФИО), менторы обновляются в белом списке по номеру телефона.
