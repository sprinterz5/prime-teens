# Рабочая тетрадь PrimeTeens — веб-версия

## Что это

`index.html` — вся тетрадь, 32 страницы, одним файлом. Открывается двойным кликом, работает без сервера, без сборки и без зависимостей. Можно сразу класть на хостинг.

Для ребёнка это выглядит так: страницы тетради листаются вниз, в поля можно печатать, чекбоксы нажимаются, в областях для рисования можно рисовать мышью или пальцем. Всё, что он написал, сохраняется автоматически.

## Что уже работает

| | |
|---|---|
| **258 полей ввода** | Все линейки для письма стали текстовыми полями |
| **10 чекбоксов** | Настоящие, кликабельные |
| **4 холста для рисования** | «Успешный успех», эскиз логотипа клуба, карта интересов, заметки |
| **Автосохранение** | `localStorage`, ключ `primeteens-workbook-v3`. Сохраняется на каждый ввод |
| **Навигация** | Выпадающий список по дням + счётчик текущей страницы |
| **Печать** | Кнопка «Печать» даёт ровно тот же A4-макет, что и PDF |
| **Адаптив** | Страница масштабируется под ширину экрана, работает на телефоне |

## Как это устроено

```
index.html          ← готовая страница, ничего больше не нужно
src/
  theme.css         ← весь визуальный язык тетради (не трогать без нужды)
  parts/*.html      ← КОНТЕНТ: сами задания, по страницам
  build_web.py      ← сборка веб-версии
  build_print.py    ← сборка печатного PDF (та же, что делала текущие PDF)
  assets/           ← логотип и шрифты в base64
```

Главное: **контент и оформление разделены**. Чтобы поменять задание, правится `src/parts/*.html`, а не `index.html`.

### Пересобрать после правок

```bash
cd src
pip install playwright && playwright install chromium   # только для печатной версии
python3 build_web.py      # → workbook_web.html
python3 build_print.py    # → PDF, с проверкой переполнения страниц
```

Веб-сборка не требует Playwright — только Python. Playwright нужен лишь для PDF.

## Как переделать под свою платформу

### Вариант 1 — оставить как есть
Залить `index.html` на хостинг. Подходит, если тетрадь одна на всех и не нужны аккаунты.

### Вариант 2 — встроить в свою платформу
Внутри `index.html` три независимых слоя, их легко разделить:

1. **Разметка страниц** — `<section class="page">`, 32 штуки. Чистый HTML без фреймворков.
2. **Стили** — `theme.css` (печатный макет) + веб-слой в конце `<style>`.
3. **Скрипт** — в самом низу файла, около 100 строк ванильного JS.

Чтобы перевести сохранение с `localStorage` на ваш бэкенд, заменяется одна функция:

```javascript
function save(){
  // было: localStorage.setItem(KEY, JSON.stringify(store));
  fetch('/api/workbook', {
    method: 'POST',
    headers: {'Content-Type':'application/json'},
    body: JSON.stringify({ userId: currentUser, data: store })
  });
}
```

Структура `store` — плоский объект: `{"p3f1": "текст", "p14f2": true, "p2f1": "data:image/png;base64,..."}`. Ключ вида `p{номер страницы}f{номер поля}` проставляется при сборке и стабилен между пересборками, пока не меняется порядок полей на странице.

### Вариант 3 — по странице за раз
Если платформа показывает по одному заданию, каждый `<section class="page">` вырезается отдельно — они самодостаточны и ни от чего не зависят, кроме CSS.

## Что стоит доделать под реальную эксплуатацию

Честно о том, чего здесь нет:

- **Нет аккаунтов.** Записи лежат в браузере конкретного устройства. Пересел за другой компьютер — тетрадь пустая. Нужен бэкенд (см. вариант 2).
- **Нет синхронизации с ментором.** Ментор не видит, что заполнил ребёнок. Если это нужно для характеристик — это тот же бэкенд плюс страница ментора.
- **Рисование простое.** Одна кисть, один цвет, кнопка «стереть». Без отмены последнего штриха и без выбора толщины.
- **Мобильный экран.** A4 на телефоне физически мелкий. Читается, но заполнять удобнее с ноутбука или планшета. Если тетрадь должна жить на телефоне — верстку заданий надо перекладывать в одну колонку, это отдельная работа.
- **Очистка необратима.** Кнопка «Очистить» стирает всё без возможности вернуть.
